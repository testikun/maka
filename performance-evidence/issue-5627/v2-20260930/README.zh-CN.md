# Transcript 极端场景优化 v2：实现与验证

日期：2026-09-30。对应[已评审方案](./DESIGN.zh-CN.md)。本轮实现基线：`8d73d4e237609dd784b816181a8e4cc2061a7579`，功能提交：`79fd458d2`，合并主分支后的交付提交：`929a30090`，PR #5712 工作树。

后续状态：`2a104db46` 已修复两个 Storybook CI 用例并同步主分支，完整本地 Storybook 与几何回归通过，见 [CI 修复与验证](./CI-FIX.zh-CN.md)。下文性能数据保留原构建身份。

## 实现与取舍

本轮实现两个独立改动：按已有 Turn 索引打开阅读位置附近的连续范围；已结束且从未展开的执行过程延迟挂载。没有新增持久表、索引、持久化正文副本、投影器、跨页投影缓存或跨会话缓存。Markdown 不作专项修改。

直达读取复用 Host 的前向页协议。页面维护一个连续范围，向上、向下阅读时自动补相邻内容；回到最新时替换为尾部范围。恢复锚点前不再补齐目标到最新消息之间的全部历史。为了不截断嵌套或交错 Turn，目标之前会读取必要的闭包前缀，目标之后按字节预算读至安全的 Turn 边界。

代价是 Desktop 必须区分订阅高水位和当前窗口终点。旧窗口不会接上跨越缺口的尾部正文，也不会确认未覆盖的尾部已读。执行观察继续运行；旧窗口中等待后台回复落盘时，通过临时尾部读取确认持久化，不强制移动阅读位置。复制、导出时，已有完整 live transcript 直接复用；否则使用独立的临时 consumer，完成后关闭，不把用户的旧窗口扩展成全部历史。

重连固定已展示窗口的上下界，不能悄悄扩展窗口。连续跳转取消前一请求，迟到结果不能覆盖新位置；取消最初打开的锚点也不会被误判为断线而触发重读。真实跳转失败进入已有错误反馈和重连恢复；临时完整读取结束时解除取消监听，避免完整历史被父读取生命周期继续引用。订阅代际、IPC 流控和既有副本预算继续沿用。

折叠过程只在第一次展示时创建内容子树，之后折叠仍保留它。运行中曾经展示的工具、思考过程，在观察中断、恢复或结束时也保持节点身份。该标记随现有 Turn 组件卸载释放，没有跨会话保存展开内容。

接受的边界：首次展开巨大过程仍会支付内容的挂载和布局成本；巨大 Turn 仍需现有完整投影；连续阅读大量历史仍会扩展当前范围。此次解决跳转距离带来的多余读取和从未展示内容的提前挂载，不建设第二套历史系统。

## 正确性验证

- 合并最新主分支 `0aa2707b5` 后，Desktop 全套 3,087 项、UI 全套 697 项通过；全工作区构建、类型检查、严格架构检查（以该主分支为基线，含 121 项规则测试）通过。合并前的功能提交也通过 Desktop 3,066 项、UI 695 项。
- 新增真实 SQLite 账本集成测试，贯穿生产 Host reader/pager、Client subscription、Main observer/registry 和 Renderer range store。覆盖定点打开、两端补页、嵌套 Turn、完整导出、断线恢复、窗口外新消息落盘、连续定位取消。
- 旧窗口与完整导出均不误标尾部已读；完整导出不替换阅读窗口；新消息确认和页面发布分别判断，避免把窗口外正文当成发送失败。
- 实窗在 1,000 Turn 历史的中段刻度（索引 507）打开 12 个 Turn，向下自动扩展为 32 个、向上扩展为 52 个；回到最新后只保留尾部 8 个。恢复后的目标在视口内，偏移约 -0.06 px。
- 新增 IPC 输入校验与双向命令转发测试；展开、折叠、运行结束及观察中断后的内容身份测试通过。
- 跳转失败和临时导出读取的生命周期回归通过；跨 Host 页与 Desktop IPC 分片的多字节正文完整重组。全量首轮发现两个旧测试缺少 Host `activeTurn` 输入，补齐运行态事实后，原显示断言及全套复测通过。

中段刻度使用索引 507，是因为现有导航栏只展示抽样刻度。测试曾请求不存在的刻度 500，超时后已排除；没有将该脚本失败记作产品恢复失败或性能样本。

## 性能方法

环境为 macOS、Apple M2 Pro、16 GiB 内存、Electron 43.4.1、production packaged build、本地隔离 Host。数据全为人工极端压力样本。普通 Turn 使用 10 次工具调用；巨大 Turn 使用 1,000 次工具调用。不能将这些结果描述为原 Issue #5627 的 Windows/WSL 活跃会话独立复现，也不能混用为 B 场景首次 Host ready 数据。

计时从真实 pointerdown 开始，终点为目标 DOM 已放置、透明度至少 0.99、再经过两个 RAF，并通过目标在视口内的断言。它不是物理屏幕呈现时间，也不保证所有后续布局都已稳定。报告区分首次 ready、目标范围 ready、正确位置可见和首次展开。

正式基线与组合实现各测 50 次，包含第一个有效返回样本，报告 p50、p95 和最大值。操作系统文件缓存不清空，因此不是冷磁盘启动测试。计时期间不同时运行本任务的编译、测试、fixture 构造或 profiler；其他系统负载未完全隔离。

四组消融为基线、仅直达、仅懒挂载、二者组合。梯度与消融的小样本只用于描述中位数和机制，不据此推断尾部概率。每个完整资源窗口还包括切到源会话、固定停留、切回、展开检查（如有）和显示后的 1.5 秒观察。CPU 为进程累计 CPU 时间差；RSS 为每 200 ms 采样的峰值，不能当作内核高水位。

先导测试发现脚本在 Turn 索引尚未返回时，把“当前第一个刻度”错当成第 0 Turn。该错误样本已保留并排除。修正后必须等待指定的 Turn ID，并校验最终位置；仅懒挂载组恢复开头仍读取 201 页，而非被误计为 2 页。

### 首次展开的代价

1,000 tools 的隐藏子树由提前创建 37,000 个后代节点，变为第一次展开前 0 个、展开后 37,000 个。首次展开 p50/p95 从 `752.1/777.2` ms 到 `877.6/963.0` ms；再次展开从 `448.0/494.2` ms 到 `465.5/779.2` ms。后者仍包含布局成本和本次环境噪声。

所以保留懒挂载的理由是：从未展开的过程不再支付挂载成本，切回 Renderer CPU 约减少 44.4%；如果用户每次立即展开这个极端过程，收益明显缩小。它没有解决 1,000 tools 展开本身的卡顿。

## 巨大 Turn 的 Host 归因

独立归因实验运行生产 reader、pager、Client 解码和 Main observer，计数与 profiler 分开执行。它测量 Host 读取路径，不是 Electron 端到端成绩。

| 读取场景 | 唯一 invocation | 投影遍数 | 唯一事件 | 累计读取/投影输入事件 | Host 页请求（不含 bootstrap） |
|---|---:|---:|---:|---:|---:|
| 100 Turn 最近历史 | 9 | 12 | 576 | 768 | 3 |
| 1,000 Turn 最近历史 | 9 | 12 | 576 | 768 | 3 |
| 单 Turn 1,000 tools | 1 | 19 | 6,004 | 114,076 | 18 |

巨大 Turn 的累计事件 payload 计数约 246 MB，实际 Host transcript payload 约 2.56 MB；消息 JSON 序列化调用累计生成约 104 MB 字节。后一个计数包含预算检查和页编码等重复序列化，不能解读成传输量或常驻内存。

独立 CPU profile 中，事件解码、SQLite 事件迭代、JSON 字节计数和事件投影均占明显份额。这些函数不是相互独立的端到端阶段，不能把累计栈耗时直接相加。计数证明了同一 invocation 被重复处理；Renderer 延迟挂载不会消除这部分工作。

取消实验在首批 Main 数据交付时关闭 consumer，之后新增投影遍数与事件数均为 0。巨大 Turn 在收到该取消之前已投影 4 遍、处理 24,016 条输入事件；这不是任意同步投影中途可立即抢占的证明。

取舍保持不变：本轮不引入跨页缓存、摘要表或部分 Turn 框架。若继续优化巨大 Turn，应单独评估一次读取操作内有界复用是否值得其生命周期、取消和内存管理成本。

## 消融与代码清理

实际删除“曾经展示过”的保留条件后，展开再折叠的节点身份断言失败，因此恢复该条件。只按当前 open 决定挂载不满足既定行为。

实际删除临时完整读取的取消监听解除操作后，重复完整读取测试观测到父 signal 监听数由 1 增至 2，断言失败；恢复清理后通过。该清理避免临时读取累积为额外保留状态。

删除了重复的 away-from-tail 可变状态写入，保留由范围和当前滚动几何推导的结果。阅读表面的接线集中在现有会话控制器中；AppShell 三个涉及文件的架构债务均未增加，严格基线检查通过。

产品代码、回归测试与本地性能实验分开管理。打包产物、数据库、profile 和临时实验脚本不混入产品提交。
